## План улучшения модели по raw waveform

### 1. Анализ текущей ситуации
- **Текущее качество**: accuracy ≈ 0.47, нулевая recall для класса `dog`, 100% recall для `rain` → возможный дисбаланс и переобучение на отдельных шаблонах.
- **Текущая модель**: `SoundClassificatonModel` — 3 блока Conv1d+BN+ReLU+Pool, затем `AdaptiveAvgPool1d(4)` и 2 полносвязных слоя.
- **Данные**: небольшой поднабор ESC (5 классов, ~по нескольку десятков примеров), есть `SimpleAudioDataset` с опцией аугментации и класс‑взвешенный `CrossEntropyLoss`.

### 2. Улучшения на уровне данных (оставаясь в wav)
- **2.1. Проверка и стабилизация препроцессинга**
  - Убедиться, что все клипы приводятся к одинаковой длине (обрезка/паддинг до 3 сек) и уровню громкости.
  - Зафиксировать `random_state` при разбиении train/valid, чтобы результаты были воспроизводимы.
- **2.2. Более целенаправленная аугментация в wav‑домене**
  - Подобрать аудио‑аугментации, совместимые с raw waveform (time shift, gain, gaussian noise, random cropping, mixup с тем же классом).
  - Усилить аугментации именно для слабых классов (`dog`, `crying_baby`), например через более высокий probability или oversampling этих классов в датасете.
- **2.3. Балансировка классов**
  - Помимо `class_weight` в лоссе рассмотреть:
    - Oversampling редких классов (дублирование примеров в train).
    - Focal Loss вместо обычного CrossEntropy для борьбы с доминированием лёгких примеров.

### 3. Архитектура модели (всё ещё только по wav)
- **3.1. Multi‑scale 1D‑свёртки**
  - Добавить параллельные Conv1d с разными `kernel_size` (например 3, 7, 15) в ранних слоях, чтобы захватывать как очень локальные, так и более протяжённые шаблоны.
  - Объединять их конкатенацией или суммированием перед следующим блоком.
- **3.2. Глобальный temporal pooling вместо жёсткого `AdaptiveAvgPool1d(4)`**
  - Использовать комбинацию `AdaptiveAvgPool1d(1)` и `AdaptiveMaxPool1d(1)` → вектор признаков меньше размерности, но информативнее.
  - Это уменьшит риск того, что модель переобучается на фиксированное разбиение временной оси.
- **3.3. Лёгкие механизмы внимания / channel weighting**
  - Вставить Squeeze‑and‑Excitation (SE) блоки над каналами feature map после 2–3 свёрточных блоков, чтобы модель училась, какие каналы важнее.
  - Вариант проще: 1–2 слоя `nn.Linear` над усреднёнными по времени признаками для reweighting каналов перед классификатором.
- **3.4. Контроль сложности и регуляризации**
  - Подобрать число каналов: возможно достаточно 16→32→64 вместо 32→64→128, чтобы снизить переобучение.
  - Усилить `Dropout` в классификаторе (например 0.5) и при необходимости добавить небольшой `Dropout` после conv-блоков.

### 4. Обучение и оптимизация
- **4.1. Тюнинг оптимизатора и learning rate**
  - Попробовать меньший базовый `lr` (например 1e-4) и/или `ReduceLROnPlateau` по валидационному лоссу.
  - Ограничить число эпох (30–40) с **ранней остановкой** по лучшему `valid_acc`/`valid_loss`, чтобы не переобучаться.
- **4.2. Улучшение стабильности обучения**
  - Включить `gradient clipping` по норме (например 1.0), чтобы избежать взрыва градиентов.
  - Проверить распределения лосса и accuracy по эпохам: сильный разрыв train/valid → усилить регуляризацию или упростить модель.
- **4.3. Потеря и метрики**
  - Рассмотреть Focal Loss для компенсации дисбаланса и улучшения по «сложным» классам.
  - Следить за **per-class recall** и macro‑F1, а не только за общей accuracy.

### 5. Анализ ошибок и целенаправленные доработки
- **5.1. Детальный разбор матрицы ошибок**
  - Посмотреть, с какими классами чаще всего путается `dog` и `crying_baby` (например, с `rain` или `sneezing`).
  - Прослушать несколько неверно классифицированных примеров, чтобы понять, хватает ли модели информативных фрагментов.
- **5.2. Работа с временными фрагментами**
  - Вместо одного целого сегмента использовать случайные кропы внутри 3 секунд на обучении, а на валидации/тесте усреднять предсказания по нескольким кропам (test‑time augmentation по времени).
  - Это даёт модели устойчивость к тому, что важный звук может быть не по центру клипа.

### 6. Экспериментальный протокол
- **6.1. Фиксация конфигураций экспериментов**
  - Явно зафиксировать конфиг с ключевыми гиперпараметрами (структура conv‑блоков, lr, augmentations, oversampling), чтобы можно было честно сравнивать версии.
- **6.2. Небольшой грид‑поиск по ключевым параметрам**
  - Количество каналов в conv‑блоках.
  - Наличие/отсутствие SE‑блоков.
  - Сила аугментаций и наличие oversampling.

### 7. Приоритеты внедрения (что делать в первую очередь)
- **Шаг 1**: Усилить аугментации в wav‑домене и балансировку (oversampling +/‑ Focal Loss), следя за per-class recall.
- **Шаг 2**: Обновить архитектуру: multi‑scale Conv1d + глобальный pooling (avg+max) и немного уменьшить количество каналов.
- **Шаг 3**: Добавить раннюю остановку, scheduler `ReduceLROnPlateau` и при необходимости gradient clipping.
- **Шаг 4**: Провести 2–3 контролируемых эксперимента и выбрать лучшую конфигурацию по macro‑F1 и стабильности per-class recall.
