# Скрипт валидации формата ноутбука

## Что делаем

Один файл (например `validate_notebook_format.py` в `DLS_Speech_HW/` или в корне), запуск:

```bash
# из корня репо, Python из .venv
.venv\Scripts\python.exe validate_notebook_format.py DLS_Speech_HW/HW_1_Feature_Construct.ipynb
```

Скрипт по шагам:

1. **Начальная валидация** — загрузка ноутбука через `nbformat.read()`, вызов `validate(nb)`. При ошибке: печать текста `NotebookValidationError` и выход с ненулевым кодом (например 1). При успехе — сообщение «Начальная валидация: ошибки» или «Начальная валидация: OK».

2. **Исправления** — работа с сырым `json` (чтение файла, правки, запись), без изменения логики кода в ячейках:
   - Для каждой **code**-ячейки: у каждого вывода в `outputs`:
     - если `output_type == 'execute_result'`: добавить `metadata` и `execution_count` при отсутствии (брать `execution_count` из ячейки);
     - если `output_type == 'display_data'`: добавить `metadata` при отсутствии;
     - если `output_type == 'stream'`: удалить ключ `metadata`, если есть;
     - у любого вывода удалить ключи, не входящие в схему nbformat v4 (например `jetTransient` и др.; явно разрешить только `stream`: `name`, `output_type`, `text`; `execute_result`/`display_data`: `data`, `metadata`, `output_type`, и для execute_result — `execution_count`);
   - Для **markdown** и **raw** ячеек: удалить ключи `outputs` и `execution_count`, если есть.

3. **Финишная валидация** — снова `nbformat.read()` + `validate(nb)`. При ошибке — печать и выход с кодом 1. При успехе — «Финишная валидация: OK» и выход 0.

## Структура кода в файле

- В начале: парсинг аргументов (путь к .ipynb), путь по умолчанию при желании — `DLS_Speech_HW/HW_1_Feature_Construct.ipynb`.
- Блок 1: функция или участок «начальная валидация» (nbformat read + validate, try/except, sys.exit(1) при ошибке).
- Блок 2: функция «применить исправления» — принимает путь к файлу, читает JSON, вносит правки по списку выше, записывает файл.
- Блок 3: после вызова исправлений — «финишная валидация» (тот же код, что в блоке 1, но после правок).
- Запуск: сначала валидация, при первой ошибке — выход; иначе исправления, затем финишная валидация.

## Зависимости

- Использовать только стандартную библиотеку для JSON и `sys`; для валидации — `nbformat` (уже ставили в .venv). В начале скрипта проверять `import nbformat` и при отсутствии выводить сообщение установить `pip install nbformat` и выходить с кодом 1.

## Итог

- Один скрипт, одна команда.
- Чёткое разбиение: начальная валидация → исправления → финишная валидация.
- После успешного прогона ноутбук проходит `nbformat.validate()` и готов к использованию с Python из `../.venv`.
